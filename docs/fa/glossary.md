# واژه‌نامه

| واژه | معنی |
|---|---|
| **Entity (موجودیت)** | یک شناسه‌ی عددی؛ خودش چیزی ندارد، componentها زیر آن نگه‌داری می‌شوند. |
| **Component (مؤلفه)** | داده‌ی ساده‌ای که به موجودیت وصل می‌شود؛ برای سریال‌سازی باید با نام ثبت شود. |
| **System (سیستم)** | یک واحد منطق شبیه‌سازی که هر گام به ترتیب ثبت اجرا می‌شود. |
| **World (جهان)** | شبیه‌سازی: موجودیت‌ها، storeها، systemها و رخدادها. |
| **Scene (صحنه)** | یک صفحه‌ی بازی؛ صاحب یک `World` تازه. |
| **Event (رخداد)** | پیامی روی `world.events` که در پایان هر گام تحویل می‌شود. |
| **Agent (عامل)** | هر چیزی که تصمیم می‌گیرد: اسکریپت، حریف AI، LLM. فقط از راه Order/Action عمل می‌کند. |
| **Behavior** | منطق تصمیم‌گیری ایمن برای یک موجودیت؛ `WorldView` می‌خواند و `Action` برمی‌گرداند. |
| **WorldView** | پنجره‌ی فقط‌خواندنیِ Behavior به جهان. |
| **Action (کنش)** | تغییر پیشنهادیِ یک Behavior که موتور اعمال می‌کند. |
| **Order (فرمان)** | قصد قابل‌سریال‌سازی در بازی نوبتی (`MoveOrder`، `AttackOrder`). |
| **Fixed timestep (گام ثابت)** | پیشروی شبیه‌سازی در گام‌های مساوی، مستقل از نرخ فریم. |
| **Fog of war (مه جنگ)** | دید جداگانه‌ی هر تیم؛ دشمنِ دیده‌نشده پنهان است. |
| **Content as data (محتوا به‌صورت داده)** | نوشتن سطح و موجودیت به‌صورت JSON به‌جای Dart. |
| **Schema (طرح‌واره)** | توصیف دست‌نویس فیلدهای JSON یک component (`zarvan_schema`). |
